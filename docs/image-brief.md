# Image brief — Hughesnet retailer site

Generate each image with the prompt below, save it under `public/images/` using the
**exact filename given**, and hand them back. Filenames are what the code will reference,
so spelling and extension matter.

## Rules that apply to every image

Each prompt already ends with these, but they are the non-negotiables:

- **No logos, brand names, text, signage, or watermarks anywhere.** A generated
  "Hughesnet" mark would be trademark misuse, and generated text almost always renders
  as garbled pseudo-lettering.
- **No identifiable faces.** People appear from behind, from the shoulders down, or
  out of frame. These are not customers or staff, and must never read as testimonials.
- **No insignia or patches on clothing** — a technician in a branded uniform implies
  employees this retailer does not have.
- **Photorealistic**, not illustration, not 3D render, not stock-photo posed.

## Palette to keep consistent across the set

Deep navy `#002B49` / `#0B2238`, cyan `#00A3E0`, warm orange accent `#FF5100`,
clean white and light slate `#F4F6F8`. Ask for a "deep navy and cyan color grade with
warm amber accents" so the set looks like one shoot rather than eleven.

## Note on resolution

Nano Banana tends to output around 1024px on the long edge. That is fine for the card
and step images. For **`hero-rural-satellite.jpg`** and **`og-share.jpg`**, generate at
the widest the tool allows and upscale to the target width before sending — those two
stretch across the full viewport and will look soft otherwise.

## Deliberately not using images

- **Plan cards** — these are pricing instruments. Photography beside a price lockup pulls
  the eye off the number and away from the qualifier and step-up rate that sit under it.
- **Pricing and terms table** — a disclosure grid. Nothing decorative belongs in it.
- **FAQ** — text comprehension section, images only add scroll length.
- **Operator logo / favicon** — cannot be designed until the real entity name replaces the
  `[Entity LLC]` placeholder in `lib/content.ts`.

## What happens when you send them back

They will be wired with `next/image`, which generates responsive `srcset`s, serves AVIF
and WebP to browsers that accept them, and lazy-loads everything below the fold. The hero
will be marked `priority` so it is preloaded rather than lazy-loaded. Each image gets
descriptive alt text; the hero and coverage backgrounds are decorative and will be marked
as such so screen readers skip them.
